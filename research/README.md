## Analysis reporting format

User preference confirmed September 5: put the exact UTC period and execution
model above each comparison, with baseline and variant statistics side by side.
Show win/loss counts and dollar amounts, not just net deltas; include averages
when useful. Separate recent and longer windows. In monthly tables distinguish
losing-cycle cost from net portfolio PnL and state how open positions and
cross-month partial exits are accounted for. Lead with the practical conclusion,
then the tables; do not mix one window's protection with another's profit cost.

## What this bundle does and does not reproduce

The [September 4 provenance manifest](../research-inputs/reproducibility/research-bundle-2026-09-04.json)
fingerprints selected sources/findings and a small set of existing generated
artifacts. These hashes identify the bytes inspected during preservation;
they do **not** establish which historical source revision originally generated
every result. The working tree was already dirty and several scripts had never
been committed. That provenance cannot be reconstructed honestly after the fact.

Specific dependencies still outside Git:

1. `backtests/hype/hl-short-study-2026-08-10/decision-features.csv` and
   `selected-trades.csv`. The generator is preserved, but there is no original
   run manifest/config/raw-input snapshot for that exact grid. Regenerating it
   from today's streams is a refresh, not proof of identical historical input.
2. `data/`, dated production logs and state used by live-led audits. Current
   syncs grow/replace these files. Copying new data over them cannot preserve an
   old experiment exactly.
3. Long wrappers depend on their particular config, cutoff and feature series.
   Matching another wrapper's totals does not by itself establish current
   live-engine parity. Maker fill microstructure, fees/funding and runtime
   downtime assumptions must be read in the actual harness.
4. The September 4 short report is based on data ending September 3 at 23:45
   UTC; local streams now extend later. Its assertions pin that earlier
   baseline. Do not weaken assertions merely to make a refresh pass.

Private data/output backup is still necessary. Git preserves the method and
conclusions, not the excluded evidence bytes. No backup or data upload is
performed by this documentation change.

## Safe reproduction and future runs

Before running a historical harness:

1. Record the source commit **and dirty diff**, config, dependency lockfile,
   runtime versions and exact command/environment overrides.
2. Inventory the required input files: SHA-256, byte size, row count, embedded
   first/last timestamps, gaps and timestamp semantics. Use a private immutable
   input snapshot; never rely on modification time alone.
3. Record decision window and outcome window separately, timezone, starting
   equity, sizing, fee/funding/slippage model, and causal availability rules.
4. Read its output paths and CLI/environment support before invocation. Several
   existing scripts default to overwriting dated output directories. The short
   grid generator also overwrites its default findings file: use
   `HL_SHORT_STUDY_OUT` and `HL_SHORT_STUDY_REPORT` for a new run. Do not assume
   every harness supports the same overrides; use an isolated research copy
   when it does not.
5. Reproduce the unchanged baseline before evaluating variants. Preserve the
   original result if parity fails; investigate the mismatch, not the threshold.
6. Record out-of-sample status honestly. A causal replay is not necessarily an
   untouched holdout; hypotheses designed after seeing losses need new evidence.
7. Write findings with sample counts, per-month deltas, limitations and exact
   source/output paths. Hash/archive outputs privately, then review source,
   manifest and findings for a path-limited commit.

No full sweeps were rerun during this preservation pass. The short report's
14-trade composition was checked directly against its existing CSV and fixed
from four TPs to two; its total and verdict did not change.
