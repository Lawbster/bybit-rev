## 3. Transfer to one actual ladder decision

Read the [exact current ladder and gate map](current-live-hype-ladder-map-2026-09-07.md)
before choosing a transfer. The economic target is lower losing dollars and
drawdown while preserving useful recovery cycles, not simply higher standalone
short win rate.

A profitable bearish short entry is **not mathematically equivalent** to a
profitable long-add veto: the long ladder owns existing exposure, average entry,
nonlinear rung sizes, changed TP thresholds and exit/cooldown state. A veto can
prevent the add that would have brought the batch TP within reach. Those lost
recoveries must be measured explicitly.

Before replay, freeze precisely:

- Whether the action governs a fresh ladder, a genuine deep price-drop add,
  a timer-based add, last-rung size, or an exit. Pick **one** per card.
- Whether evidence is a fresh crossing or a persistent state, when it expires,
  what happens if missing, and how release works. Do not silently turn a4h
  one-off short signal into an indefinitely latched long prohibition.
- Existing gate precedence and unaffected protection/TP/partial/flatten paths.
  No simultaneous sizing, timer, cooldown or TP redesign.
- The exact current copied config/state assumptions, cost model, windows,
  repaired input hashes and previously accepted canonical replay contract.

Reproduce the **current repaired canonical replay** at zero variant before
testing modifications. Do not use the known legacy `sim-exact.ts` bias as
the definition of correct parity. Preserve the existing replay's explicit
TP-fill assumptions and maker/funding/receipt-time limitations instead of
calling it exchange-perfect.

Run the full history supported by each source and the identical healthy rich
overlap; keep continuous occupancy and all state changes. Report baseline next
to every variant: W/L counts, winning/losing dollars, net/open mark, DD, monthly
deltas, extra/foregone TP cycles, avoided/new forced closes and exposure.
Attribute the actual changed ladder episodes, including invisible recovery
costs. Standalone dollars must not be added to ladder dollars.

## Stop / continue rule

The stages are not a promise that an indicator will earn live deployment.
If known-time context adds no robust incremental information, retain the
negative result. If it does not transfer to the ladder, retain the unchanged
ladder rather than optimizing gates until one period looks good.

Do not remove sample, monthly, cost, causality or concentration failures from
earlier records. Fresh observations after a prospectively fixed cutoff are
separate evidence; repeated historical refinements are not a forward test.

push or deployment have been performed by R01 or this handoff document.
